# IF OJ 디자인 기준

기준 시안: `if_oj_demo_v4.html`. 흰색 표면, 군청색 강조, 상단 내비게이션, 행 형태의 그룹·문제집 목록을 사용한다.

- `tokens.css`: 색상·글꼴·모서리 등 공통 값. 새로운 화면은 기존 토큰을 먼저 사용한다.
- `global.css`: 버튼·패널·상태 배지·입력·로딩·오류·빈 목록 공통 표현.
- `ui.jsx`: Button, Icon, StatusBadge, AsyncState, CopyButton. 비슷한 UI를 새로 만들기 전에 재사용한다.
- `layout/AppHeader.jsx`: 공통 로고·내비게이션·사용자 영역.
- `../App.css`: 기능 화면의 레이아웃과 반응형 배치.

기본 본문 최대 너비 1120px, 패널 모서리 15px, 폼 모서리 9px. 980px 이하는 메뉴를 두 번째 줄로 옮긴다. 600px 이하는 여백을 14px로 줄이고 예제 입출력을 한 열로 배치한다. 키보드 포커스, 실제 label, 오류/로딩 안내, 빈 결과를 모든 화면에 제공한다. 동적 제목과 문제 내용은 줄바꿈을 허용하고 pre/code는 내부에서 스크롤한다.

목록 API의 `isSolved: false`는 제출 여부나 오답을 구분하지 못하므로 **미해결**로 표시한다. `true`는 **맞았습니다**로 표시한다. 제출 결과의 AC/WA/CE/TLE 등은 서버 응답을 그대로 사용해 공통 배지로 표현한다. 임의로 채점 결과·제출 통계·성능 수치를 만들지 않는다.

기존 `src/api` 호출과 SSE/폴링 흐름을 재사용한다. 새로운 API 또는 응답 필드가 필요하면 사용자에게 요청하고 프론트 디자인 작업 중 구현하지 않는다. 시안의 데모 설정과 가상 채점 로직은 제품 코드에 넣지 않는다.

새 화면을 추가할 때 이 문서와 가장 가까운 기존 화면을 확인하고, 공통 UI가 새로 필요하면 이 디렉터리에 추가한다. 디자인 변경 후 실제 API 형식을 사용하는 검증 데이터로 주요 이동·오류·모바일 레이아웃을 확인한다.
